## 修复编辑模式左右滚动同步误差

- 现象：编辑模式下滚动时，左预览与右编辑器内容错位（左在「九、」右在「## 六、」），且误差随内容累积。
- 根因：旧逻辑用「源码行号 × lineHeight」换算编辑器滚动位置（`centerEditorAtSourceLine`），但 `<textarea>`（`.editor`，13px / line-height 1.7，soft wrap）里长段落会软换行成多个视觉行，一个源码行 ≠ 一行像素，误差不断累积。
- 修复（`src/renderer/app.js`）：
  - 新增「镜像测量」方案：后台隐藏 div（与编辑器 fontFamily/fontSize/lineHeight/padding/clientWidth/white-space:pre-wrap 完全一致），用 Range API 测任意字符偏移的真实像素 y（`editorPixelYForOffset` / `editorOffsetForPixelY` 二分反查）。
  - 双向同步全部改走像素映射：`centerEditorAtOffset`、`centerEditorAtSourceLine(line, tab)`、`syncPreviewScrollFromEditor`（中心像素 → 偏移 → 源码行）、`scrollEditorToSource(offset)` 直测偏移；`toggleEdit` 调用补传 tab。
  - 删除了废弃的 `editorLineMetrics`。
- 验证：`node --check` 通过；smoke.js 失败系 node_modules 未安装（环境问题，非本次改动）。
- 待办：用户重启应用实测；打包新版需 `npm i` 后走 dist 流程。
